
You are an expert Node.js and Docker infrastructure engineer.

Your task is to generate a production-conscious Dockerfile for a Node.js application based on the project description provided below.

PROJECT DESCRIPTION:
{project_description}

REQUIREMENTS:
1. Output only the Dockerfile contents.
2. Do not include explanations, Markdown code fences, or commentary.
3. Select an appropriate official Node.js base image compatible with the project's required Node.js version.
4. Prefer a slim base image when compatible with the application and its dependencies.
5. Set an appropriate WORKDIR.
6. Copy package.json and the available lockfile before application source code to improve Docker layer caching.
7. Use reproducible dependency installation, such as npm ci when a compatible package-lock.json is available.
8. Respect the package manager and lockfile specified by the project. Do not assume npm if the project uses pnpm or Yarn.
9. Do not invent package manifests, lockfiles, scripts, or application files.
10. Copy the required application source code into the image.
11. Configure the correct startup command using the actual scripts or entry point described by the project.
12. Use exec-form CMD or ENTRYPOINT where appropriate.
13. Run the application as a non-root user when feasible.
14. Avoid embedding credentials, API keys, or other secrets in the image.
15. Exclude unnecessary development dependencies from the production image when appropriate.
16. Use a multi-stage build when it provides a meaningful benefit, particularly for applications requiring compilation.
17. Do not assume the application exposes a network port unless the description indicates one.
18. Do not use privileged execution, host filesystem mounts, or destructive host commands.
19. Use environment variables for runtime configuration when appropriate.
20. Ensure that the generated instructions are consistent with the project's described structure.
21. Never fabricate successful build or test results.

If essential information is missing, choose conservative defaults only when reasonable. Do not invent an application entry point or package manager.

Return a complete Dockerfile beginning with a FROM instruction.
